# Design Patterns

## Behaviour Pattern
1. [State Pattern](./state_pattern.md)
1. [Strategy Pattern](./strategy_pattern.md) :
  The **Strategy pattern** defines a family of algos, encapsulates each one and make them interchangeable. Strategy lets he algo vary independently from client that use it.
1. [Observer Pattern](./observer_pattern.md) :
  The **Observer Pattern** defines a one-to-many dependency between objects so that one object changes state, all of its dependents are notified and updated automatically.
1. [Command Pattern](./command_pattern.md)

## Design Principles
1. Identify the aspects of your application that vary and separate them from what stays the same.
2. Program to an interface, not an implementation.
3. Favor composition over inheritance.
